# Base-paper accuracy and evaluation protocol audit

Audited 2026-09-28 from the project's local copy of Pardede, Solikhun, and Ismail, *Comparative Analysis of EfficientNet-B0 and MobileNetV3-large Architectures for Imbalanced Multiclass Skin Lesion Classification*, [Journal of Image and Graphics 14(4), 551-566](https://www.joig.net/show-111-558-1.html). This audit concerns comparability; it does not claim to reconstruct the authors' unreleased code.

The paper reports **98.86% EfficientNet-B0 test accuracy** and **98.88% MobileNetV3-Large test accuracy**. It says its HAM10000 data are split 70/15/15, but its Table IV (page 561) lists test support **7,041**, with about **1,006 images in each of seven classes**. Fifteen percent of the original 10,015 HAM10000 images is about **1,502**, and the original dermatofibroma class has only 115 images. The reported table therefore cannot describe an untouched 15% sample of the original dataset. It closely matches a 15% sample of a fully balanced dataset: seven classes × 6,705 majority-class images = 46,935; 15% is 7,040.25.

The methods text is internally inconsistent. One passage says RandomOverSampler acts only on training data, while another says the balanced and preprocessed dataset is subsequently partitioned 70/15/15. Table IV supports the latter sequence or another evaluation on replicated images. Without code and image IDs, the exact implementation cannot be proven. If replicated minority images were split across train and test, copies of the same original image could appear on both sides and substantially inflate test accuracy. At minimum, the 98.86% figure is **not comparable** to our untouched original-image validation or lesion-disjoint validation. The paper also describes resizing from native 28×28 RGB, whereas the HAM10000 originals in this project are 600×450, another method-description mismatch.

We can cite the paper's architecture and balancing ablations as reported, then report our own experiments under their actual split labels. We should not present their 98.86% and our strict scores as if they came from the same evaluation protocol, nor create a replicated-image test set to chase that number. The locked strict test set remains untouched.
