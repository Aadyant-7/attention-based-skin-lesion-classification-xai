# Audit of high HAM10000 accuracy claims

Checked 2026-09-28. The repository's locked strict test images were not opened or evaluated. These are methodological comparisons, not endorsements of the reported scores.

| Source | Headline | What the paper or executable code actually evaluates | Consequence for comparison |
|---|---|---|---|
| [Pardede et al., Journal of Image and Graphics 2026](https://www.joig.net/show-111-558-1.html) | 98.86% EfficientNet-B0 and 98.88% MobileNetV3-Large HAM10000 test accuracy. | The full paper's Table IV reports **7,041 balanced test cases**, about 1,006 in every class. An untouched 15% test slice of the 10,015 original images would contain about 1,502. The table instead closely matches splitting a dataset balanced to 6,705 images per class. Its text conflicts about whether RandomOverSampler ran before or after partitioning; code and test IDs are unavailable. | The test table cannot represent an untouched original-image 15% split. If duplicated minority images crossed partitions, test accuracy could be strongly inflated. See [local protocol audit](base_paper_protocol_audit.md). |
| [Deep Ensemble Model, Applied Sciences 2024](https://dspace.ewha.ac.kr/bitstream/2015.oak/269416/1/applsci-14-05599.pdf) | 96% “HAM10000” balanced accuracy; 97% ISIC. | The paper's HAM10000 evaluation uses **three selected categories** (melanoma, BCC, and AKIEC/SCC), not the original seven-category benchmark. It reports 90% on the original HAM subset and 96% on a balanced oversampled version. It describes 75/25 random splitting but does not establish lesion-ID grouping or a clean duplicate audit for the balanced evaluation. | The 96% is not a seven-class HAM10000 accuracy. A balanced test distribution is also a different target population. |
| [InceptionResNetV2 + Soft Attention code](https://github.com/skrantidatta/Attention-based-Skin-Cancer-Classification/blob/main/Ham10000%20models/Best%20Model%20with%20different%20Test%20Train%20splits/IRV2%2BSA_15split.ipynb) | About 93.8% on seven classes. | The actual notebook first selects **singleton lesion IDs** (`groupby('lesion_id').count()`, then count==1), draws a stratified 15% test sample from those, and puts every other image into training. It makes about 8,000 offline augmented training images **per class**, uses ImageNet InceptionResNetV2 at 299² with a 16-head spatial soft-attention module, trains up to 150 epochs, and feeds the `test_batches` generator to `model.fit(..., validation_data=...)`. The best weights are selected by accuracy on that same test cohort. The split has no fixed seed in the displayed `train_test_split` call. | The apparent test cohort excludes all multi-image lesions and is reused for model selection; it is not an independent final test of the selected checkpoint. The 299² attention architecture and large augmentation pool remain plausible useful methods, but reproducing its claim exactly would require substantial compute and still not match our strict benchmark. |
| [Naim Hassan Saykat et al. public ensemble repository](https://github.com/md-naim-hassan-saykat/skin-lesion-classification-ensemble-ham10000) | 95.91% ViT and 93.86% ensemble internal accuracy. | The maintainers explicitly state archived checkpoints came from different historical data partitions and the common 2,003-image cohort is retrospective, not a universal untouched test. Their ViT scores 66.51% on the separate harmonized ISIC2019 cohort. | The high internal number cannot be treated as a strict lesion-disjoint held-out estimate. |
| [Multimodal ALBEF HAM10000 preprint](https://www.medrxiv.org/content/10.1101/2024.05.30.24308213v3.full) | 94.11% with image plus age/sex/site. | The paper reports a random 70/20/10 **image** split, up to 200 epochs, multimodal transformer, and checkpoint selection on validation. It does not report a lesion-ID overlap audit in the methods inspected. | This protocol is materially different from our fixed lesion-grouped split; our cheap metadata probe on the strict split showed no meaningful benefit. |
| [EfficientNetV2-L + attention preprint](https://arxiv.org/html/2601.00964v1) | 91.15% accuracy, 85.45% macro F1. | 384² input, about 120M parameters, staged 60-epoch schedule, strong augmentation, 70/15/15 image-count split on two 16GB T4 GPUs; no released implementation or lesion-overlap proof found. | Potential architecture/resolution evidence, but neither attainable cheaply at the same scale on our 8GB GPU nor verified to use our evaluation protocol. |

The reports above contain real methodological differences. Their headline percentages cannot be substituted for the project's strict result. In particular, three-class evaluation, balancing an evaluation population, retrospective cohorts, validation reuse, and lesion-selection rules can all materially alter a number labeled “HAM10000 accuracy.”

## Cheap experiment before another training run

The frozen exploratory 224-pixel B0+CBAM checkpoint scored 0.8622754491017964 accuracy and 0.7807634025293032 macro F1. Re-running it at 384 pixels alone scored 0.8276779773785762 and 0.6824743347439389, but a fixed equal probability average of 224+384 improved to **0.872255489021956 / 0.7877714099879248**. Thus high-resolution predictions add complementary errors even when individually weaker.

On the same exploratory validation split, a fixed equal-probability average of the original and stronger-augmentation saved checkpoints at **224 and 384 pixels each** scored **0.8815701929474384 accuracy and 0.8280078815327692 macro F1**. This uses *no new training* and beats both constituent checkpoints by both measures. Including 320-pixel predictions reduced the six-stream average to 0.8749168330006654 / 0.8106700584942095. Source metrics and per-class confusion matrices are in `results/exploratory/resolution_probe/` and `results/exploratory/multires_ensemble/`.

This remains a **validation-selected exploratory image-level result**, with 596 validation images sharing a lesion ID with training. It is not a clean 88.16% test score or evidence of >93% final accuracy. Its value is a reproducible, compute-cheap inference improvement. The frozen-checkpoint predictor is `scripts/predict_exploratory_ensemble.py`; for example, run `python -m scripts.predict_exploratory_ensemble --image path/to/lesion.jpg` from the repository root. It averages the two saved checkpoints at 224 and 384 pixels with four equal weights.

That strict check was completed with the original weighted and oversampled checkpoints. The best fixed two-model/two-resolution accuracy candidate scored **0.8562874251497006** with macro F1 **0.7479786346921041**, below the preexisting strict leaders (accuracy 0.8589487691284099 after prior correction; macro F1 0.7718103328854748). The 224-pixel controls exactly reproduced their saved metrics. Full strict results are in `results/strict_multires_probe/`. Thus the multiresolution gain did **not** transfer to the lesion-disjoint split; report it only on the exploratory track.

A further no-training subgroup audit of the four-stream exploratory ensemble found **0.9252110977080821 accuracy on 829 singleton-lesion validation images**, compared with 0.825503355704698 on 596 validation images sharing a lesion with training and 0.8461538461538461 on 78 other multi-image validation cases. The singleton subset contains **648/829 (78.2%) nevus images**, compared with 1,007/1,503 (67.0%) in the full exploratory validation pool. Its 92.52% is therefore strongly affected by case mix and is not a representative all-lesion accuracy. The published attention notebook also selects singleton lesions for its test set, but its exact class mix differs; these percentages are not directly comparable. See `results/exploratory/multires_ensemble/subgroup_audit.json`.

The 93% requirement remains unmet on the full validation cohort. The next training step, if any, must be a short pilot with an explicit stop rule; a new 20–150-epoch architecture search is not justified by these results.
