## Repository diagnosis and ranked hypotheses

1. **Evaluation protocol and cohort effects.** Our split has zero lesion overlap; a code-inspected image-level implementation groups by class only. In HAM10000, repeated lesion images make this a concrete source of optimistic evaluation. Its magnitude here is unknown until a controlled run.
2. **Overfitting under weak augmentation.** Weighted run ended at train accuracy .9678 versus validation .8450; oversampled run reached .9977 versus .8456. Current training only flips horizontally. Stronger but medically plausible transforms could reduce memorization, particularly for repeated minority examples.
3. **Resolution / geometry and model capacity.** All 7,009 sampled train originals are 600×450, mapped to 224². That loses detail and changes aspect ratio. The inference-only center-crop diagnostic performed worse, but also removed field of view, so it cannot rule out training at 300–384 pixels with matched preprocessing. EfficientNetV2-L paper differs on both capacity and resolution, so its gain cannot be attributed to one variable.
4. **Loss/prior and class confusion.** Melanoma↔nevus errors dominate. Oversampling, focal loss, MC dropout, metadata fusion, and prior correction all failed to improve both accuracy and macro F1; this reduces the priority of another loss-only or inference-only tweak.
5. **CBAM placement / classifier design.** Our sole CBAM follows the final 7×7-ish feature map, where spatial information is coarse. Earlier attention is plausible, but the supporting study is binary with extra data and cannot justify a multi-block training run ahead of the protocol check.
6. **Data-label noise and acquisition shift.** HAM10000 combines sources and has labels established by multiple confirmation methods. We have no validated audit assigning a fraction of the plateau to label noise or patient shift; this remains speculative.

## Single selected experiment

**`image_level_weighted_b0_cbam_v1`**, exploratory image-level protocol comparison. `scripts/train_image_level_protocol.py` creates `data/splits/exploratory/image_level_dev_v1.csv` by stratifying **only** the 8,512 images in the strict train+validation development pool into 7,009 train and 1,503 validation images. The original 1,503 strict test images retain their `test` assignment and are never loaded for training or inference. This new split has **563 lesion IDs spanning train and validation; 596 validation images have a lesion also present in training**. Accordingly its scores are explicitly weaker-protocol results, never leakage-safe validation or test performance.

The model, ImageNet weights, 224² transforms, weighted CE, optimizer, schedule, batch size, epoch cap, patience, seed, and macro-F1 checkpoint selection match `configs/first_run.json`. This isolates the main protocol contrast better than changing backbone, augmentation, and split simultaneously. The two validation cohorts are still different, so observed differences combine split leakage and sample composition; the experiment diagnoses protocol sensitivity, not a causal leakage effect. If it nears or exceeds 90%, the original strict plateau likely reflects methodological comparability more than a simple implementation error. If it stays near 85%, the next strict experiment should prioritize stronger augmentation with matched training/inference geometry.

Expected duration is approximately 15–25 minutes on the local RTX 4060, extrapolated from the original weighted run and 7,009 training images per epoch. Stop after five stale macro-F1 epochs; abort at epoch 12 if best validation accuracy remains below .82. Files are separated under `results/exploratory/` and `checkpoints/exploratory/`. Report accuracy **and** macro F1; no result is assumed in advance.

## Completed first probe and next controlled run

The first probe finished all 20 epochs in 616.1 seconds. Its best epoch was 19: **0.8622754491017964 validation accuracy and 0.7807634025293032 macro F1**; weighted F1 was 0.8622647732797672 and validation loss 0.4371838058064322. Training accuracy reached 0.9647595948066772 by epoch 20. The score exceeds the earlier strict maxima numerically, but the validation images and leakage properties differ, so the difference cannot be credited solely to shared-lesion exposure. It remains far below 90%. The complete stored result is `results/exploratory/image_level_weighted_b0_cbam_v1_summary.json`, and the epoch history is `results/exploratory/image_level_weighted_b0_cbam_v1_history.csv`. Its local best checkpoint is `checkpoints/exploratory/image_level_weighted_b0_cbam_v1/best.pt` and is preserved.

The next run, `image_level_strong_aug_b0_cbam_v1`, uses the **same exploratory split, pretrained backbone, CBAM, loss, optimizer, scheduler, batch size, and 224² validation transform**. Its sole intended change is training augmentation: horizontal and vertical flips, ±20° rotation, small translation/scale affine transform, and mild brightness/contrast/saturation/hue jitter. This follows the direction of the code-inspected [EfficientNet-B2 augmentation implementation](https://github.com/nicolasagra-dev/efficientnet-skin-lesion-classification/blob/main/skin_lesion_classifier/data.py) without changing architecture or evaluation protocol. The hypothesis is that extra visual diversity reduces the observed train–validation gap. A useful result should exceed the first probe's 0.862275 accuracy **without reducing** 0.780763 macro F1; otherwise this recipe does not advance both goals. Runtime estimate: about 12–20 minutes on the same GPU. Early stopping and the epoch-12 low-accuracy criterion remain active. This run has its own checkpoint and result paths.

### Strong-augmentation outcome and compute decision

The run completed 20 epochs in 1,003.2 seconds. The macro-F1-selected best checkpoint was epoch 18: **0.852960745176314 accuracy and 0.7657417116155746 macro F1**, both below the baseline on the same exploratory validation set by **0.0093147039254824 accuracy** and **0.0150216909137286 macro F1**. The final epoch's 0.8536260811709914 accuracy and 0.7456911246729765 macro F1 did not change the conclusion. Training accuracy was 0.885861 at epoch 20 versus 0.964760 for the first recipe. The increased augmentation reduced memorization, but the saved checkpoint did not generalize better by either primary metric. Macro recall increased (.765147 → .807058) while macro precision fell (.802282 → .733014); nevus recall fell (.936445 → .914598). This tradeoff is not a convincing accuracy gain.

The full result and history are `results/exploratory/image_level_strong_aug_b0_cbam_v1_summary.json` and `results/exploratory/image_level_strong_aug_b0_cbam_v1_history.csv`; the preserved local checkpoint is `checkpoints/exploratory/image_level_strong_aug_b0_cbam_v1/best.pt`. The error log was empty. No strict test image was used.

**Decision:** Do not run another broad 20-epoch trial from these observations alone. The image-level protocol change produced only a modest gain, and this stronger augmentation recipe regressed despite ~17 minutes of compute. A further expensive experiment needs a specific failure mechanism and a cheap discriminating check first. The current exploratory leader remains `image_level_weighted_b0_cbam_v1`; the strict-track leaders remain in the frozen snapshot.

## Frozen-checkpoint inference follow-up

A no-training four-stream average of the two exploratory checkpoints at 224 and 384 pixels each reached **0.8815701929474384 accuracy and 0.8280078815327692 macro F1** on the same exploratory validation set. The original 224-pixel checkpoint alone scored 0.8622754491017964 / 0.7807634025293032. The executable predictor is `scripts/predict_exploratory_ensemble.py`, and the validation recipe and per-class results are in `results/exploratory/multires_ensemble/`. This is an image-level, validation-selected result, not a strict test estimate.

The identical principle failed to improve the lesion-disjoint strict validation leaders: the best checked strict variant reached 0.8562874251497006 accuracy and 0.7479786346921041 macro F1. This limits the four-stream result to the exploratory track. A [source-level audit](high_accuracy_claims_audit.md) details why several public 93–96% headlines use substantially different class sets, selected populations, or held-out rules. No 93% seven-class strict result has been established here, and no further training was launched for this follow-up.
